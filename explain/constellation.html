Constellation explained

The control surface for a governed project twin.

Constellation is the place a human can see project state, ask grounded questions, and understand what is ready, what is inferred, and what still needs a source or reviewer.

Open the live product

Jr is the approachable face. The machinery underneath stays governed.

How to think about it

The dashboard is the face. Jr is the guide. NotebookLM handles grounded text questions. Multimodal RAG is the intended path for drawings and visuals. The world model holds structured state. Human review decides what can be relied on.

1

Human asks a question or opens a project view.

2

Constellation routes the request to the right role, notebook, skill, or data loader.

3

The answer returns with a source chain, an inference marker, or a stop condition.

4

A reviewer upgrades authority only when the source and approval path support it.

System layers

Thin harness

Flask routes, pages, static assets, and deterministic seams.

Configuration and data

Project definitions, role definitions, notebook routing, and project data loaders.

Intent resolver

Maps questions to the right Jr mode, skill, and answer shape.

Fat skills

Markdown work instructions carry judgment, process, and construction doctrine.

Grounding engines

NotebookLM for source-backed text. Visual RAG for drawings and photos when approved.

World model

Structured objects with source reference, authority level, validation state, owners, and next action.

Boundary

This explanation is not contract authority, Sage authority, owner approval, field direction, payment support, or project-control validation. It is a map of how the system works and where the real sources must be checked.
